## 🔑 Основные файлы

### Уровень приложения

#### `app_main.py`
- **Назначение**: основной сервис FastAPI, обрабатывает все WebSocket-соединения
- **Основные функции**:
  - Управление маршрутами WebSocket (/ws/camera, /ws_audio, /ws/viewer и др.)
  - Загрузка и инициализация моделей
  - Координация и управление состоянием
  - Раздача аудио- и видеопотоков
- **Зависимости**: все остальные модули
- **Точка входа**: `python app_main.py`

#### `navigation_master.py`
- **Назначение**: управление навигацией, автомат состояний всей системы
- **Основные состояния**:
  - IDLE: ожидание
  - CHAT: режим диалога
  - BLINDPATH_NAV: навигация по тактильной дорожке
  - CROSSING: переход улицы
  - TRAFFIC_LIGHT_DETECTION: детекция светофора
  - ITEM_SEARCH: поиск предмета
- **Основные методы**:
  - `process_frame()`: обработка каждого кадра
  - `start_blind_path_navigation()`: запуск навигации по дорожке
  - `start_crossing()`: запуск режима перехода улицы
  - `on_voice_command()`: обработка голосовой команды

### Рабочие процессы

#### `workflow_blindpath.py`
- **Назначение**: основная логика навигации по тактильной дорожке
- **Основные функции**:
  - Сегментация и детекция дорожки
  - Детекция препятствий
  - Детекция поворотов
  - Стабилизация оптическим потоком
  - Формирование подсказок направления
- **Автомат состояний**:
  - ONBOARDING: выход на дорожку
  - NAVIGATING: движение
  - MANEUVERING_TURN: поворот
  - AVOIDING_OBSTACLE: обход препятствия

#### `workflow_crossstreet.py`
- **Назначение**: логика навигации при переходе улицы
- **Основные функции**:
  - Детекция зебры
  - Выравнивание по направлению
  - Формирование подсказок
- **Основные методы**:
  - `_is_crosswalk_near()`: близко ли зебра
  - `_compute_angle_and_offset()`: вычисление угла и смещения

#### `yolomedia.py`
- **Назначение**: поиск предметов
- **Основные функции**:
  - Детекция YOLO-E по текстовой подсказке
  - Отслеживание рук MediaPipe
  - Отслеживание цели оптическим потоком
  - Наведение руки (подсказки направления)
  - Распознавание захвата
- **Режимы**:
  - SEGMENT: детекция
  - FLASH: мигающее подтверждение
  - CENTER_GUIDE: наведение на центр
  - TRACK: отслеживание руки

### Речь

#### `asr_core.py`
- **Назначение**: потоковое распознавание речи Alibaba Cloud Paraformer ASR
- **Основные функции**:
  - Распознавание речи в реальном времени
  - VAD (детекция речевой активности)
  - Обратные вызовы с результатами
- **Ключевой класс**: `ASRCallback`

#### `omni_client.py`
- **Назначение**: клиент мультимодального диалога Qwen-Omni-Turbo
- **Основные функции**:
  - Потоковая генерация ответа
  - Ввод изображение + текст
  - Голосовой вывод
- **Основная функция**: `stream_chat()`

#### `audio_player.py`
- **Назначение**: единое управление воспроизведением звука
- **Основные функции**:
  - Воспроизведение TTS
  - Многоканальное микширование
  - Управление громкостью
  - Потокобезопасное воспроизведение
- **Основные функции**: `play_voice_text()`, `play_audio_threadsafe()`

### Бэкенды моделей

#### `yoloe_backend.py`
- **Назначение**: бэкенд детекции YOLO-E с открытым словарём
- **Основные функции**:
  - Задание текстовых подсказок
  - Сегментация в реальном времени
  - Отслеживание целей
- **Основной класс**: `YoloEBackend`

#### `trafficlight_detection.py`
- **Назначение**: детекция светофора
- **Способы детекции**:
  1. Модель YOLO
  2. Классификация по цвету в HSV (запасной вариант)
- **Выход**: красный / зелёный / жёлтый / неизвестно

#### `obstacle_detector_client.py`
- **Назначение**: клиент детекции препятствий
- **Основные функции**:
  - Фильтр классов по белому списку
  - Детекция внутри маски пути
  - Расчёт свойств объекта (площадь, положение, опасность)

### Обработка видео

#### `bridge_io.py`
- **Назначение**: потокобезопасная буферизация и раздача кадров
- **Основные функции**:
  - Схема «производитель — потребитель»
  - Кэш исходных кадров
  - Раздача обработанных кадров
- **Основные функции**:
  - `push_raw_jpeg()`: приём кадра с ESP32
  - `wait_raw_bgr()`: получение исходного кадра
  - `send_vis_bgr()`: отправка обработанного кадра

#### `sync_recorder.py`
- **Назначение**: синхронная запись видео и звука
- **Основные функции**:
  - Одновременная запись видео и звука
  - Автоматические имена файлов (по времени)
  - Потокобезопасность
- **Выход**: `recordings/video_*.avi`, `audio_*.wav`

### Веб-интерфейс

#### `templates/index.html`
- **Назначение**: веб-интерфейс мониторинга
- **Основные области**:
  - Видеопоток
  - Панель состояния
  - 3D-визуализация IMU
  - Результаты распознавания речи

#### `static/main.js`
- **Назначение**: основная логика JavaScript
- **Основные функции**:
  - Управление WebSocket-соединениями
  - Обновление UI
  - Обработка событий

#### `static/vision.js`
- **Назначение**: обработка видеопотока
- **Основные функции**:
  - Приём кадров по WebSocket
  - Отрисовка на Canvas
  - Подсчёт FPS

#### `static/visualizer.js`
- **Назначение**: 3D-визуализация IMU (Three.js)
- **Основные функции**:
  - Приём данных IMU
  - Отрисовка ориентации устройства в реальном времени
  - Динамическое освещение

## 🔄 Потоки данных

### Видео
```
ESP32-CAM 
  → [JPEG] WebSocket /ws/camera 
  → bridge_io.push_raw_jpeg() 
  → yolomedia / navigation_master 
  → bridge_io.send_vis_bgr() 
  → [JPEG] WebSocket /ws/viewer 
  → Browser Canvas
```

### Звук (вверх, к серверу)
```
ESP32-MIC 
  → [PCM16] WebSocket /ws_audio 
  → asr_core 
  → DashScope ASR 
  → результат распознавания 
  → start_ai_with_text_custom()
```

### Звук (вниз, к устройству)
```
Qwen-Omni / TTS 
  → audio_player 
  → [PCM16] audio_stream 
  → [WAV] HTTP /stream.wav 
  → ESP32-Speaker
```

### Данные IMU
```
ESP32-IMU 
  → [JSON] UDP 12345 
  → process_imu_and_maybe_store() 
  → [JSON] WebSocket /ws 
  → visualizer.js (Three.js)
```

## 🎯 Основные паттерны

### 1. Автомат состояний
- **Где**: `navigation_master.py`
- **Зачем**: управление переходами между состояниями системы
- **Состояния**: IDLE → CHAT / BLINDPATH_NAV / CROSSING / ...

### 2. Производитель — потребитель
- **Где**: `bridge_io.py`
- **Зачем**: развязать приём и обработку видео
- **Реализация**: потоки + очередь

### 3. Стратегия
- **Где**: все `workflow_*.py`
- **Зачем**: реализации разных стратегий навигации
- **Реализация**: единый интерфейс `process_frame()`

### 4. Одиночка (Singleton)
- **Где**: загрузка моделей
- **Зачем**: общие экземпляры моделей на всё приложение
- **Реализация**: глобальные переменные + проверка инициализации

### 5. Наблюдатель
- **Где**: обмен по WebSocket
- **Зачем**: подписка нескольких клиентов на видеопоток
- **Реализация**: `camera_viewers: Set[WebSocket]`

## 🚀 Порядок запуска

1. **Инициализация** (`app_main.py`)
   - Загрузка переменных окружения
   - Загрузка моделей навигации (YOLO, MediaPipe)
   - Инициализация звуковой подсистемы
   - Запуск записи
   - Предзагрузка модели светофора

2. **Запуск сервиса** (FastAPI)
   - Регистрация маршрутов WebSocket
   - Подключение статических файлов
   - Запуск приёма по UDP (IMU)
   - Запуск HTTP-сервиса (порт 8081)

3. **Работа**
   - Ожидание подключения ESP32
   - Приём видео / звука / IMU
   - Обработка голосовых команд пользователя
   - Отправка результатов обработки в реальном времени

4. **Завершение**
   - Остановка записи (сохранение файлов)
   - Закрытие всех WebSocket-соединений
   - Освобождение ресурсов моделей
   - Удаление временных файлов
